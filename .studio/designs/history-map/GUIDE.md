# 历史地图桌

一张桌上的地图承接地点和局势变化。镜头贴近纸面时，军旗、村舍和人物立牌组成小景。画面配中文纸牌，无旁白。随卡示例为 16:9、1920×1080、18 秒，[三皇会战 · 拿破仑](example/DESIGN.md)。片长由作品决定。

## 1. 选题与范围

选一场战役或整场战争，用一句话写出能在地图上看见的变化。从 `example/SCRIPT.md` 的镜头纲要起步，定好人物视角、起止日期和地理范围。地图先给出阵营与地点，进入小景再让观众看到其中一项变化。

## 2. 填两张史料表

复制 `RESEARCH.template.md`。事实表为每张画面牌登记原文、所依据的事实和出处。史实底线表登记不能画错的细节，例如军帽、军服、人物是否在场、旗帜年代、地图方位。争议说法省略，或在牌面标「一说」。在 `ANIMATION_PLAN.template.md` 引用两个表及对应编号。Plan 门的人工确认包含两张表。填写示例见 `example/RESEARCH.md` 与 `example/ANIMATION_PLAN.md`。

## 3. 编镜头表

用地图总览交代方位，俯冲到纸片小景呈现一项动作，再返回地图交代后果。较长的片子可按战区、年份或阶段分组，每组重新交代地理关系。一般信息牌留约 2.5–4 秒，示例保留自身 18 秒的快速提示节奏。以实际观看时间核对能否读完。

用思源黑体。以 1080 高计，信息字至少 48 px，日期和关键数字至少 76 px。同屏最多两张信息卡。可读字与主要动作放在 x 120–1800、y 110–800，y 820 以下不放要读的字。正式工程用 `page` 布局，检查翻牌、旋转和缩放的实际边界。示例另有 `standalone` 放映布局，日期在左上角，适合独立对照。

### 战斗大场面

战斗镜头要撑得起大场面，不要只拿三四队士兵就当作大场面。三皇会战示例就是照下面几条反复返工出来的：

- 画面要满。前景、中景、远景都要有队伍。小景、地图总览和转场里，连成一片、什么都没有的空地图都不超过画面的约 1/4。下方三分之一可以放被画框切掉一部分的前景队伍或骑兵，只是不放要读的字。
- 兵要大、要多。以 1080 高计，最近一排兵身高约 220 px 以上，中景约 120 px 以上，远处用密集纵队纸片撑人数。每个战斗镜头中段，主力一方要能数出约 80 人以上，另一方也要有几十人；以少打多时，人数差要一眼看得出。骑兵按人头算。
- 成排复制不露馅。同一张纸片复制成排时，每份的大小相差约 ±8 %，偏角和步伐相位也错开，相邻两份不要一样；后排压暗、放虚。同一张图共用一张贴图，多份用实例化绘制。
- 要动起来。步兵先行进再射击：走或跑 → 站定换成齐射纸片 → 枪口亮火光 → 队前留一条硝烟带再慢慢散开。骑兵按纸偶的节奏一跳一跳地冲，不要平滑滑行。
- 爆炸用单独的纸片图。落地土柱、空中开花、爆后烟柱各备一张，按 12 fps 换片：一两帧内蹦到最大，再换成烟柱升起、淡出。大小、角度、镜像和落点按种子错开。炮口和枪口用火光纸片。
- 用粒子表现枪林弹雨。齐射时成片的短亮线从枪口飞向对面，打到墙上和地上溅起火星与雪土。炮弹是带淡烟尾的暗点，走抛物线，落点接爆炸图。粒子位置每帧按 t 直接算出。
- 敌我分得清。对阵两军之间留出一段看得见的空地，弹道从中间飞过。
- 统帅看得清。主角不要是远处的一个小人，可以骑马、带随员放在前景。
- 素材备齐。一场仗至少备好：行进、齐射、冲锋、撤退四种步兵纸片，密集纵队、骑兵、炮组，以及爆炸、火光和硝烟带。人物、队伍和骑兵纸片不能水平翻转，翻了朝向和旗帜会错；爆炸、烟和火光可以翻转。

## 4. 准备纸片

可用有确切出处的公共领域原图，也可生成或手绘。画风用低饱和色、纸面颗粒、细墨线和奶白模切边。人物的脚、马蹄和车轮要画完整。提供透明底 WebP，去多余透明边，按画面近景使用的实际长边取样。提交前逐件看图：

- 帽型、军服和旗帜符合表中的年代、兵种与阵营，人物出场位置正确。
- 检查朝向、植地、遮挡、纸边和轮廓。两侧可见的纸偶要核对背纸，薄纸群像要核对侧看效果。
- 检查输出图中的文字。地图地名优先使用 DOM 牌，素材中的可读字也要列入文字清单。
- 确认素材出处、发布许可和文件摘要。参见 `ASSETS.md`。

## 5. 接线草稿

在明确选择 `history-map` 的作品里备好 Plan。初次复用可以物化示例，再把同相对路径的工程源文件复制到自己的可编辑工程。保留工程已有的 `project-config.json` 声明，合并示例的 `snapshot_dependencies`，保留工程本地运行库与冻结外观。安装资产时用实际的 `--work`、`--variant` 与 Plan 中的 `history-map/world@v1`、`history-map/plates@v1`；按命令帮助提供 Binding 和 scene。独立练习可以用 `component install … --project <目录>`。同一素材的多张纸偶可共用一次 `diecut` 结果。

| 资产 | 调用与数据 |
|---|---|
| `history-map/world` | `await createWorld({canvas, quality})` 建立地图桌。`sheet({data, center, rot, ppu})` 接大小、道路、溪流、鱼塘、丘陵和村落的数据。`diecut(img, options)` 制作轮廓。`makeCard(dc, {height, solid, batch})` 返回 `set(pose)`，薄纸批量提交仅用于同底图的普通纸片。`groundY(x,z)` 取地面高。`setCamera(camera)`, `setLight(preset, target, span)` 和 `render(post)` 接作品自己的镜头和光照表。`fogSheet`、`paperSmoke` 与 `battleParticles(world, items)` 接作品自己的画面效果时序。`medium` 对应示例，`high` 提高贴图与后期采样。 |
| `history-map/plates` | `createPlates(overlay, {fontFamily, sides, mode})`，用 `load(spec)` 一次建好纸牌并等待 `ready`，然后 `apply(t)`。`date` 日期、`cards` 信息、`names` 人名、`labels` 地名、`pills` 对读、`banners` 横标、`tables` 比较、`counters` 计数、`quotes` 引文。常规牌记录 `id/from/to`，挂点牌加 `anchor`（屏幕点或以秒数返回点的函数）及 `place`。日期用 `at/year/date/sub`。用 `layoutAt(t)` 和 `texts()` 查布局和内容。 |

本卡片子模块接口为 `create({canvas, overlay, fontFamily, seed, quality, mode}) → {ready, apply(t), dispose}`。作品模块将地图、镜头、纸牌和动作各自写成表，如 `example/napoleon.js`。`seed` 可用于初始化可复算的程序图形，示例为贴合参考帧使用固定种子。`apply(t)` 取当前秒数，重算镜头、卡片、烟粒子和牌子。四个根层为 `background`、`stage`、`overlay`、`text`。画布挂 `stage`，中文牌挂 `text` 或 `overlay`。Canvas 或 WebGL 若新增地名或其他文字，用 `texts()` 完整列出，并把读表回调登记到 `window.__hfTextSources`，字段按宿主的嵌入文字合同填写。示例地图无画布文字，返回空清单。

把宿主同一次安装中的 `gsap.min.js` 和同版本的 `MotionPathPlugin.min.js` 复制到工程的 `runtime/`，沿用工程已有的 `runtime/three.min.js`。在入口按示例顺序加载本地时间线脚本、路径插件和三维运行库，把三条路径加入 `snapshot_dependencies`。示例清单复用公开字体文件与字体许可。使用已冻结 Theme 时，先加载外观与字体，把可用字体名交给片子模块。等待 `film.ready` 后注册一条暂停的主时间线。在宿主 `hf-seek` 中按时刻定位并调用 `film.apply(t)`，通过 `waitUntil` 告知宿主何时可以取帧。动画以定位秒数为准。`dispose()` 释放实例的 DOM、资源和监听。示例 `scene.js` 包含完整接线。

本卡跳过 TTS、cues 和 beats。可完全静音，或将自行准备并取得授权的音乐作为工程内本地音轨，以 `data-audio-role="stem"` 声明。

## 6. 检查

用 `work design validate history-map` 和 `work design preview history-map` 查内置示例。自制工程先跑 `plan check`，再登记并诊断草稿。前跳、回拖、重复定位，逐帧看阵营方向、服装、字牌和遮挡。用 `renderer.info` 统计负载时，设 `autoReset=false`，每次 `apply(t)` 前 `reset()`，统计场景与后期的总提交次数。

## 7. 导出

通过 Plan 门和完整草稿的人工确认，按通用流程制作封面并执行 `finalize`。查看输出画幅、时长、字体和安全区。静音片核对音轨数量为零，有音乐的片核对本地音轨和时长。
